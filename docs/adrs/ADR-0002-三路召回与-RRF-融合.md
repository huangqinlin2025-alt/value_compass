# ADR-0002：三路召回 + 加权 RRF 融合

- 状态：accepted
- 日期：2026-09-18
- 相关：`docs/design/retrieval.md`

## 背景

财报问答强依赖**精确数字、会计科目、专有名词**。单路向量检索面临两个问题：

1. "营业收入 1,815,972,101" 这类字面量的语义向量与"营收多少"并不天然接近；
2. 在默认 Hashing Embedding（无语义）下，向量路几乎退化成随机召回。

## 备选方案

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 单路向量 | 简单 | 数字/专名召回差；换 embedding 才能救 |
| 单路 BM25 | 精确命中强 | 无泛化，问法一变就漏 |
| 向量 + BM25 双路，分数加权相加 | 简单 | 两路分数量纲不同，加权系数难以调 |
| **三路 + 加权 RRF** | 只用排名，免疫量纲；可插拔增减路数 | 需要维护三路索引一致性 |

## 决策

1. 三路并行召回：**BM25（精确） / 向量（语义） / 元数据过滤（范围）**；
2. 融合用加权 RRF：`score(d) = Σ w_i / (60 + rank_i(d))`，
   默认 `w_bm25=1.0 / w_vector=1.0 / w_meta=0.6`，`table_flag` 乘 1.15；
3. 意图驱动权重：数字类意图（METRIC/CALC）把 BM25 提到 1.3，语义类（QUALITATIVE/SUMMARY）把向量提到 1.3；
4. 三路**必须基于同一份 chunk 快照**（`index/snapshots/{doc_id}.pkl`），否则引用页码会错位。

## 后果

- 正面：任一路故障不影响整体（部分成功即可继续）；换 embedding 只影响其中一路；
- 负面：需要同时维护 BM25 倒排与向量库，入库链路更重；
- 已发现的坑：RRF 第一名未必是字面最相关的块，因此**相关性闸门取前 5 候选的最优值**而非只看 top1。
